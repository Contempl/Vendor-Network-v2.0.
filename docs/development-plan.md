# План развития Vendor Network

## Рабочий цикл

Каждый этап выполняем в отдельной ветке: реализация, ревью, автоматические проверки, ручная проверка и разбор кода, коммит и push, PR, проверка CI, merge в `development`.

Основная рабочая копия остаётся на `development`. Для текущей задачи используем один отдельный worktree рядом с проектом. После merge обновляем основную копию и проверяем её состояние, затем удаляем завершённую ветку и её worktree через Git. Временные скрипты и диагностические файлы храним в игнорируемой `.local/`, локальные секреты — в игнорируемых `.env`. Новые рабочие копии в Temp не создаём.

## Текущий этап: основа мониторинга

Реализованы:

- Метрики HTTP, PostgreSQL и .NET runtime через OpenTelemetry, Collector и Prometheus.
- Traces HTTP и запросов PostgreSQL в Tempo; очистка чувствительных атрибутов.
- JSON-логи с `traceId`, ответный HTTP-заголовок `X-Trace-Id`.
- Health endpoints для проверки API и его зависимостей.
- Provisioning Grafana, источников данных и дашборда API.
- Чтение настроек через `IOptions<ObservabilityOptions>` с валидацией при запуске.
- Ротация Docker-логов и ограничения хранения метрик и traces.
- Автоматические проверки и отдельный smoke test мониторинга в CI.

Завершение этапа: финальное ревью, проверки, коммит и push, PR, CI и merge. Устройство мониторинга и локальный запуск описаны в [monitoring.md](monitoring.md).

## Следующие отдельные этапы

### 1. Централизованные логи: Loki и Alloy

- Сбор JSON-логов приложения и доставка в Loki.
- Поиск логов в Grafana по сервису, уровню и `traceId`.
- Переход от записи лога к соответствующему trace в Tempo.
- Срок хранения логов и меры по ограничению занимаемого места.
- Проверка защиты секретов и чувствительных данных.

### 2. Оповещения

- Правила для роста HTTP 5xx и задержки запросов с учётом объёма трафика.
- Проверка доступности API и зависимостей.
- Настройка канала уведомлений и проверка срабатывания и восстановления.
- Хранение правил в Git и их проверка в CI.

### 3. Доработка CI, включая frontend

Отдельный запланированный этап.

- Воспроизводимая установка пакетов через `npm ci`.
- ESLint, проверка типов TypeScript и production build Next.js.
- Отдельные jobs для backend, frontend и мониторинга.
- Обязательные успешные checks перед merge PR.
- Кеши загрузки зависимостей, таймауты, диагностические артефакты и отмена устаревших запусков.
- Дополнительные тесты клиента для сценариев регистрации, входа и разграничения доступа.

## Отдельная задача PostgreSQL

Проверить предупреждение о несовпадении версий collation. До изменений сделать и проверить резервную копию, определить затронутые индексы и выполнить необходимые шаги обслуживания. Обновление метаданных версии collation само по себе не перестраивает индексы.

## Последующие задачи

- Аудит действий пользователей и администраторов в бизнесах.
- Надёжная отправка приглашений и уведомлений через transactional outbox.
- Отдельный пересмотр аутентификации и авторизации, включая возможность подключения Keycloak. Сохранить различие между SuperAdmin приложения и Admin конкретного бизнеса.
- Решение о переходе к микросервисам принимать после оценки границ модулей и эксплуатационных затрат.
